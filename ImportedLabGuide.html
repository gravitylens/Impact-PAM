Ignite World Tour: IT Infrastructure Lab


Introduction to Kyndryl

Before beginning the exercises, here are a few tips to help you navigate the labs more effectively. Understanding these will make for a much more enjoyable lab experience.

Kyndryl Interface

Once connected to the Kyndryl environment, you will see the following screen. This interface displays a virtual machine on the left side and the lab guide on the right side.

Using the Guide on Small Screens

The lab manual typically appears as a panel on the right side of the virtual machine. This layout is more effective on larger screens, enabling side-by-side viewing of the lab and instructions. However, it may be challenging to navigate on smaller screens that lack sufficient space for all content. Several features are available to assist with this issue.

Resize the Guide

You can shrink the size of the right panel to allow more space for the virtual machine.

If the displayed images are too small, click on the image to view them in full-screen.

Pop out the Guide

You can Pop out the guide to move it to a separate browser tab or on another monitor. This allows you to collapse the lab manual panel, maximizing screen space for the virtual machine.


Copy and Paste

It is possible to copy/paste between a virtual machine and your local machine. Kyndryl will attempt to do this whenever you use ctrl-c or ctrl-v in a virtual machine. However, this can be unreliable as it may have trouble syncing with your local clipboard. For better results, use the clipboard button on the Kyndryl Toolbar to transfer your endpoint clipboard to the virtual machine directly. Right-clicking to copy and paste will only work with the VM clipboard.

There is also copyable text throughout the guide. You can paste that value into the VM with a right-click or ctrl-v whenever you click on one of these copyable texts. Be patient, as it usually takes a second or two to work.

Tips for Maximum Productivity

Use the Kyndryl Toolbar on the virtual machine to maximize your ability to interact with that machine efficiently.

Fit to Window

The Fit to Window icon will resize your virtual screen to adapt to your computer's screen settings to avoid scrolling. Putting your browser in full-screen mode also creates more screen space for the virtual machine and minimizes distractions.

Bandwidth Settings

You may need to adjust your bandwidth settings for slower connections. This will reduce the image quality of the connection and conserve bandwidth.

Kyndryl recommends at least 1.2 Mbps bandwidth per VM console session running. Latency is usually the most significant cause of poor performance.

Ctrl-Alt-Del

Use the Ctrl-Alt-Del button on the toolbar to send a Ctrl-Alt-Del to the virtual machine.

Using VPNs

Connecting to Kyndryl while using a VPN may introduce additional network latency. It can also mislead the GeoIP locator system in Kyndryl, potentially provisioning your lab in a suboptimal region, which could exacerbate latency issues. To enhance the responsiveness of virtual machines, avoid using VPN connections whenever possible.

Global Users

The lab machines are configured to use a US-English keyboard layout by default. If you use a machine with a different keyboard layout, you may experience odd behavior from your lab machines. The solution is to install the keyboard layout for your keyboard on your lab machines. Follow the process below to find and configure the correct keyboard layout for your keyboard.

On the VM, click on the Start Menu, go to Settings | Time & Language | Language | Add a language.

Select your language. Click Next. Uncheck the options for voice and handwriting, and then click Install.

Note: If you use an alternate keyboard layout (e.g., AZERTY, Dvorak), you can click the options next to your language to install that. Otherwise, close the Language window.

In the system tray, click ENG, then choose your keyboard layout. You may switch back and forth between keyboard layouts.

Section 2: Secure Access to Long-lived Windows Systems using Zero-standing Privileges (ZSP)

2-1 Connect to a Windows VM using ZSP

In this exercise, we will connect to a Windows VM using zero-standing privileges.

SIA for zero standing privileges access works differently for each target type. For a Windows target, SIA creates an ephemeral user and adds it to a local group on the target. Then, the SIA connector redirects the RDP session to the target, without allowing any inbound connectivity into the customer’s environment. This method enables the user to work on the target with a domain or local user that has the appropriate permissions.

The ACME administrator already created a policy to grant you access via ZSP.

  1. Return to the Access space, navigate to Infrastructure and click on Add target.
  2. Select Windows and click on Continue.
  3. Enter the following address:  %{metadata:PPA_Address}  and click on Add Target
  4. Note the target has been added, but the username field is empty.
  5. Hover over the target and then click on the Connect button.
  6. Click on the RDP file to launch the session. If prompted about the publisher, select "Don't ask me again for connections to this computer" and click Connect.
  7. On the target machine, click the Windows search icon in the taskbar, type lusrmgr.msc  and press Enter.
  8. Under the Local Users and Groups -> Groups open the Remote Desktop Users group.
  9. Verify you can see your ephemeral user ID identified by the user's name followed by a random string.

    When you connect to a Windows VM using ZSP, CyberArk creates an ephemeral account in the target system and adds it to a local group, in this case, Remote Desktop Users. This method ensures no permissions are associated with the credentials you used to access the target system until they are needed, and they are removed again at the end of the session. This approach minimizes the security risks associated with standing access.
  10. Close the lusrmgr windows and Sign out of the RDP session.

A personal account is quicker to create and more straightforward to manage than a regular account. This capability frees Privilege Cloud administrators from performing preliminary tasks for newly provisioned end users creating new accounts.

We will then use the PPA account to connect to a long-lived Windows target via CyberArk Secure Infrastructure Access (SIA).

    Address acme.corp
    Username %{metadata:PPA_Username}
    Password Cyberark1

A personal privileged account is scheduled for automatic Verification when added to the Vault. After the account is successfully verified, additional actions such as Change and Reconcile password will also be available. This ensures that only the end user who owns the account and, therefore, knows the password can successfully onboard and manage the account. 

The Verify task can take a few minutes, so for the sake of efficiency, we will not wait for the Verify action to complete or initiate a Change task, which would be required in the real world. Instead, we will proceed right away to the next section and connect with the account.

When using this feature, users connect to targets with credentials that are managed in the Privilege Cloud Vault with little or no associated permissions. Upon connecting to a target system, users receive only a selected range of relevant permissions defined in the appropriate policy. At the end of the user’s session, these permissions are removed.

With this workflow, users can access Windows targets on a just-in-time basis, with time-bound sessions. Security teams can meanwhile maintain the existing user profiles of an account, including key credential management and rotation policies

The target account will be removed from the local group when we disconnect.

Section 5: Threat Detection and Response 

In this section, we will review the Suspicious Activities in Sessions IT alert supported by Threat Detection and Response.

Threat Detection and Response enables organizations to automatically identify and address privileged security events. Continuous monitoring of identity systems helps detect suspicious activities and potential threats by analyzing logs, user behaviors, and system interactions for anomalies. Immediate actions, such as notifying security teams, isolating compromised accounts, and activating incident response protocols, are essential for containing and mitigating threats.

Section 6: Secure AI Agents

In this section, we will provide a high-level overview of the secure AI agents capability, and you will set up an AI assistant to execute database tasks via our AI Gateway using natural language.

We can secure agents by registering them in the inventory of authorized agents, creating an identity for the AI agent, and directing access to tools and databases through the Secure Infrastructure Access MCP server via the AI Agents Gateway. Our policies ensure least privilege and zero standing privileges, granting access solely for specific tasks and revoking it afterward. Audits capture who initiated the agent (human user), which AI agent identity acted, which tools ran, and which resource (database) was touched.

Various AI-powered tools can be utilized, provided they support connections to remote MCP servers via OAuth 2.1. Notable examples include Claude, Copilot, and others. For this exercise, we will use Le Chat, an AI assistant developed by Mistral AI, a company based in France.

8-1 Create and run alias commands

Rather than copying the full SIA connection command from the Access space, we can simplify the process of creating reusable connection aliases for secure system access using CyberArk's scripts, without the need to connect to the web UI. The script will save the alias commands in your default shell environment. For this exercise, the Windows script has already been saved on your machine. Once you run the script for the first time, the following alias commands are ready to use :

  • cybr-ssh  Runs the SSH command for users who prefer not to use MFA caching or are unable to use it.
  • cybr-sso  Runs the SSH command using an MFA caching key.
  1. Click the PowerShell shortcut on your taskbar.
  2. Execute the script .\cyberarkscript.ps1 
  3. Enter acme-lab-1774 as your CyberArk tenant name 
  4. Provide your user ID %{metadata:CPC_Username} when prompted for your full username.
  5. Hit the Enter key when prompted for the path where the key will be saved. 
  6. You will receive a summary of the alias creation and be prompted to close and reopen the window. Press the Enter key and Close the PowerShell window. 
  7. Relaunch PowerShell from the taskbar.
  8. Enter the command  cybr-sso <instanceID> replacing instanceID with the AWS Linux VM instance ID from the previous exercise. 
  9. If prompted for the RSA key fingerprint question enter yes and press Enter. 
  10. Enter Cyberark2 as your Password and press Enter. (Note that if you were not asked to reset your password at the start of the lab, use the default one Cyberark1)

    When executing the alias command utilizing MFA caching, the script checks for a valid MFA key. If it's not present, it prompts for authentication. Upon successful authentication, the script retrieves the MFA key and establishes a connection, setting up a secure session with the target. Subsequent sessions will use this key, negating the need for re-authentication within the MFA caching period.
  11. Verify you were able to connect to the target Linux VM.
  12. Type exit to exit the SSH session.
  13. Run the cybr-sso <instanceID> command again. Verify you can connect without having to type your password again.
